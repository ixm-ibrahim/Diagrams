# 01 Processing Queries

How a thread handles anything the author sends. This file exists because past attempts drowned in their own reference files: the AI read everything once, worked from fading memory as its context filled, and made mistakes. The cure is a fixed routine with the reading built in at the moment it is needed — never from memory. When in doubt, or after any long stretch of work, re-read this file; it is short on purpose.

## At thread start

1. Read [[02 - Derivation Rules]] in full — the rules, the node format, the template.
2. Read [[03 - Demystification]] and [[04 - Common Biases]] in full — they govern all writing and all checking.
3. Skim [[00 - Table of Contents]] to know what exists. The remaining files — [[08 - Unresolved Objections]], [[05 - Pending Links]], [[06 - Phenomenological Dictionary]], [[07 - Objection Index]], [[09 - AI Thesaurus]], [[10 - Sentence Case Studies]] — are look-up files: consult them at the moments named below (the thesaurus before proposing any fix for a flagged word; the case studies whenever a sentence stays awkward through more than one rewording), and do not try to hold them in memory.

## On each message from the author

1. Read the message twice, and list every separate ask in it — his messages often carry several.
2. Decide what each ask is — a filled node template, a fix or a ruling, a new rule, a question — and handle each in order. Before responding to any point of his, represent it back first — restate what he is saying, at its strongest — and only then answer; this applies to everything he says (his instruction).
3. If any ask is unclear, ask him: one question, told as a complete self-contained story. Never guess silently.
4. Check every response of his for new rules to add to the system, and for modifications or refinements of existing rules — he states them in passing as often as directly (his instruction). Add each to the right reference file in his words — and apply it to the current work before moving on.
5. His corrections state principles, not spot-fixes: each one applies uniformly everywhere — to the whole current text, the other reference files, and all future work — not just to the instance he pointed at. This mindset binds every thread, and every helper a thread spawns learns it too (his instruction). Whatever is newly learned — a banned word, a principle, a caught pattern — triggers a fresh sweep of all existing pages, and of the reference files' own examples where the lesson touches them (his instruction; the first such sweep found banned words living inside the writing rules' own good examples, where the standard itself was reproducing them).
6. If he corrects a misreading, the correction goes into the affected text itself, not just the conversation — the next reader will bring the same bias.

## When working a node

1. Open the entry with three things: the question it must answer; inspiration from his own material, quoted word for word with the source file named (checked against that file first — inspiration stays in chat, never in the note); and the blank template from [[02 - Derivation Rules]].
2. He types; you verify. Check every load-bearing word of the Definition against [[06 - Phenomenological Dictionary]] — a word granted by a later node cannot be used. Check each new objection against [[07 - Objection Index]] — its answer may already exist at another level; an objection belonging to a different level goes to [[08 - Unresolved Objections]].
3. Report problems one at a time in chat, each a complete story that quotes the node text it concerns — enough context that he can rule without opening the page (his instruction) — and each checked against [[04 - Common Biases]] before sending — a bias shared with the reader does not look like a bias. He fixes in his words; suggestions are welcome, but only what he accepts enters the record.
4. Whenever node-page text is produced or checked: list every sentence containing a conditionally banned word (the list lives in [[03 - Demystification]]) for the author — he rules on each sentence (his instruction). Any new text added to a page later goes through the same passes a draft gets — the writing self-check in [[03 - Demystification]], the banned-word listing, and the missing-example look — before he sees it; text added mid-life is not exempt (his catch).
5. At the end of the first complete draft of any page: spawn a helper that hunts the draft for common AI words and phrases NOT yet on the banned list, and report its finds to the author with examples, so he decides what gets added — and for anything he adds, list every instance with a proposed replacement for his agree-or-disagree, case by case (his instruction).
6. When the node looks done, spawn one fresh helper per kind of effort, each seeing only what its check needs, each disclosed in one line:
 - format, against [[02 - Derivation Rules]];
 - writing, against [[03 - Demystification]] and [[04 - Common Biases]];
 - logic, for the concept layer — each argument establishes what it claims, each objection's commitments genuinely support it, each reply answers the commitment it names, nothing assumes what it concludes; sound, clear logic is the highest priority of the whole effort (his instruction);
 - examples, hunting for points that are invisible without an example and have none, against the example rule in [[03 - Demystification]] (his instruction);
 - consistency, across the reference files (dictionary entries both directions, pending links both directions, objection index, table of contents).
7. State every finding to him in chat, plainly. Apply his fixes, re-check just the fixes, and loop steps 6–7 until the helpers return clean and he says it reads right.
8. Then finish: update [[00 - Table of Contents]], [[05 - Pending Links]], [[06 - Phenomenological Dictionary]], and [[07 - Objection Index]]; go through all previously made pages and add links between relevant nodes, in both directions — beyond what [[05 - Pending Links]] already queues (his instruction); delete the old note on the same term from tmp-dump if one exists. The node awaits the author's ok. Snapshots in the file history belong to the master thread — never run git.
9. Before printing any final output or return: re-read the current rules files (they may have changed mid-thread) and check the output against them, and scan the output itself for any ruling of his that has not yet been recorded (his instruction — thread's reading of its scope, open to his correction).

## Context hygiene

- Every change carries its bookkeeping with it, in the same pass (his instruction): a word replacement he ratifies goes into [[09 - AI Thesaurus]]; a fix with a lesson goes into [[10 - Sentence Case Studies]]; a new link-in-waiting goes into [[05 - Pending Links]]; a new term ruling reaches [[06 - Phenomenological Dictionary]]; a new rule reaches its rules file. Never let a ruling live only in chat.
- Temporary and process files — handoffs, changes lists, and any other working file the AI makes that is not part of the record — live in their own folder, "Temporary Files", beside the Phenomenological Grounding folder, so nothing process-shaped sits inside the digital brain (his instruction; the PP1 changes list moved there). The tmp-dump folder is different — it holds his old notes under its own rule in [[00 - Table of Contents]].
- Never work from memory of a rule — open the file and look.
- After roughly every ten exchanges, or whenever unsure what the standard is, re-read this file and [[02 - Derivation Rules]].
- If context is running low, say so and write the return while quality is still high — a clean early handoff beats a degraded finish.
