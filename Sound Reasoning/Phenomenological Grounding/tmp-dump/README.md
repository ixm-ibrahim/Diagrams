# README — how this folder works

This folder is the **phenomenological grounding**: every term the project uses, each defined only from words already given meaning, tracing back to the first given ("phenomena occur"). One note per term. The author's ruling (2026-09-02): the vault is the brain for all things philosophy, with the grounding as one folder inside it. The handoff had proposed a new folder inside Comparative Religion; in the master thread's first sitting the author ruled instead that the brain lives here, in the existing Sound Reasoning vault, keeping that vault's name — and named this folder "phenomenological grounding" himself. Other domains of his work can join later as sibling folders, and notes can link across them.

Start at [[00 Map]] — it links to everything.

## Opening this vault in Obsidian

Obsidian is already installed on this computer. (On a new computer: download it free from obsidian.md, no account needed, install it, then follow the same steps.) To open the vault:

1. Open Obsidian (search "Obsidian" in the Start menu).
2. If "Sound Reasoning" appears in the vault list, open it. If not: choose **Open folder as vault** and pick `Documents\Personal\Diagrams\Sound Reasoning`.
3. The **graph view** is the button in the left sidebar that looks like dots joined by lines (or press Ctrl+G). Every note is a dot; every `[[link]]` is a line between dots.
4. Click any dot to open that note.

## How to read a note

Every term note has the same parts:

- **Definition** — only ever the author's own typed words, quoted, with the date and the source file. If the note is a stub, there is no definition yet — only the question the term must answer, and inspiration material clearly marked as not live wording.
- **Direct parents** — the already-defined terms this definition's wording uses, one line each. Parents inherit from their own parents, so the chain above a note shows exactly which words were available at its depth.
- **Words this term makes available** — what later definitions may use once this note stands.
- **Examples** — the author's own, marked as his.
- **Open flags** — anything awaiting the author's word, each written as a complete story.

## The three statuses (in the note's frontmatter)

- **ratified** — the wording is the author's typed words: either typed fresh in a sitting and dated, or verbatim-his from his notes and messages, verified against the source file and cited. Two disclosed edge cases from the first pass, each stated plainly on its own note: three entries are his formulas with only the head-word renamed by his own 2026-09-02 swap ruling (Soundness, Unsoundness, Soundness-value), and one definition survives in a sealed return that quotes him rather than in a file he typed directly (Context).
- **in-progress** — the author is working on it now.
- **stub** — not started. The note holds only the question this term must answer and the inspiration material, marked "inspiration only — not live wording."

## Bookkeeping conventions (this vault's, not project vocabulary)

- The frontmatter id mirrors his raw-notes item number where one exists ("NOTES item 5"). Several terms can share one id when his single line defines several terms (his item 3 defines qualities and associations; his item 4 defines will, temporal qualia, and scope). Terms with no source item say "none yet".
- Filenames are the bare term for now. The handoff's format is "id plus term" (like "A3 Qualities.md"), but those ids come from sections — so ids join the filenames when the author names the sections, and the renaming will be done mechanically with every link updated.
- The parentheticals in titles like "Grounded (of a proof)" keep two jobs of one word apart until the author writes the real names.

## The one rule that governs everything (the author's, 2026-09-02)

The author types every wording himself. Nothing here is AI-drafted language for him to approve with a yes or a no — that is how contaminated wording entered the record before. Inspiration material is quoted verbatim from his own earlier files with its source named, and he writes the new wording in his own words. The thread then verifies his work: every word checked against what the parent chain makes available, counterexamples hunted through his own machinery, collisions checked against already-ratified notes, and his inspiration material compared for anything the new wording lost. Problems are reported plainly, one at a time, and he fixes them in his own words. The same rule covers names — section names included: he writes them, the thread checks them.
