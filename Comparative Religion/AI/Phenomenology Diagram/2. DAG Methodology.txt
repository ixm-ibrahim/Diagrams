======================================
==  The Directed Acyclic Graph (DAG)
==  Methodology for Phenomenological
==  Construction
======================================

This document outlines the formal method for constructing a rigorous and verifiable map of experience. The goal is to build complex concepts from primitive observations without circular definitions or hidden assumptions.

--[ 1. The Core Principle: Phenomenological Purity ]--

Every node in the DAG must describe only what occurs in experience or what is logically derived from such descriptions.

This principle has three immediate consequences:

1.  **No Experiencer Assumption**: The construction must not assume an "experiencer," "self," or "agent" at the start. Terms like "I" or "we" are high-level concepts that must be derived later. Start with what occurs, not who it occurs to.
2.  **No Causal Claims**: The DAG describes patterns of co-occurrence and succession ("this follows that"), not their underlying causes ("this *makes* that happen"). Causal theories must be constructed later from these observed patterns.
3.  **No Metaphysical Substrates**: The DAG labels phenomena (e.g., "redness occurs"), not their supposed foundations (e.g., "redness exists in a substance").

--[ 2. The Structure: Anatomy of a Node ]--

Each concept is a "node" in the graph. Every node MUST contain these six components:

| Component          | Purpose                                           |
|--------------------|---------------------------------------------------|
| **ID** | A unique identifier for reference (e.g., PH1, T4). |
| **Statement** | A single, concise, declarative sentence stating the phenomenological observation. |
| **Inherits From** | The ID(s) of the parent node(s) that provide the terms used in the Statement. This is mandatory for all but primitive nodes. |
| **Terms Introduced** | A list of new words licensed by this node. This should ideally be one primary term plus synonyms. |
| **Question Addressed** | The specific phenomenological question that this node answers, arising from its parents. |
| **Intuitive Example** | A concrete, relatable instance of the observation to ground the abstract statement.            |

--[ 3. The Rules of Construction ]--

1.  **One Node, One Idea**: Each node should introduce only one primary concept. This prevents conceptual overloading and ensures clarity.
2.  **Strict Inheritance**: A node may ONLY use terms introduced by its parents or its parents' ancestors. There are no exceptions. This is the central rule that guarantees rigor.
3.  **No Forward Reference**: A node can never, under any circumstance, use a term defined in a node that comes after it.
4.  **Start with Primitives**: The DAG begins with a handful of "primitive nodes" that inherit from nothing. These are phenomenological axioms—observations so basic they cannot be further reduced (e.g., "Phenomena occur"). They can only be recognized or not.

--[ 4. How to Read and Navigate the DAG ]--

1.  **Read Non-Linearly**: The document's sequence is for organizational purposes only. The true structure is the inheritance network. When you read node T4 and see it inherits from IA2, you must jump to IA2 to understand its foundation, regardless of where IA2 is on the page.
2.  **Trace Dependencies**: To fully understand any concept, trace its "Inherits From" list back to the primitive nodes. This reveals its complete logical foundation.
3.  **Trust the Acyclicity**: The "Acyclic" property of the DAG mathematically guarantees that there are no hidden circular definitions, no matter how long the inheritance chain. A concept can never loop back and depend on itself.

--[ 5. How to Add a New Node ]--

1.  **Identify the Gap**: What question remains unanswered by the existing nodes?
2.  **Determine Parents**: Which existing nodes provide the precise vocabulary needed to ask and answer this question?
3.  **Formulate the Statement**: Write a single, clear sentence describing the new observation, using ONLY inherited terms.
4.  **Introduce the Term**: Give a label to this new pattern/observation.
5.  **Provide an Example**: Find a clear, unambiguous example of the phenomenon.
6.  **Verify Rigor**: Check every word in your new Statement. Does it have a clear inheritance path back to a primitive? If not, you have found a hidden assumption and must define the missing term first.
