# Structural Rules and Derivation Principles

These ensure the tree's dependency order mirrors valid reasoning, and that
each claim is verifiable and non-circular.

---

## Formatting Conventions

1. **Quotation marks** = personal statements only (Node 1's claim, 1.7).
   Don't quote every claim.

2. **Title prefixes** only where they add qualifying context.
   "Phenomenological Grounding: ..." = useful. "Reasoning verifies..." =
   already clear, no prefix needed.

3. **Page structure:** 4-space indent = children within same page. Deeper
   dot notation (1.2.5.1.x) = new sub-page.

---

## Structural Rules

### Observation → Identification → Induction

4. **Observation before abstraction.** When a node identifies a general
   pattern, the specific observation grounding it must appear first.

5. **States before processes.** When a state and process appear
   interdependent, define the state first. The process operates on it.

6. **No circular dependencies.** Every concept in a definition must be
   grounded in a prior node or direct observation. If A uses B, B must
   not use A.

7. **No hidden assumptions.** Every dependency is a prior node or direct
   observation.

8. **Terminal nodes must be self-evident** from direct experience.

9. **Ontological simultaneity, epistemological ordering.** Everything exists
   simultaneously in experience. The tree models the order of
   *identification*, not existence. Each node performs a different epistemic
   act — noticing something new using what was already noticed.

   **9b. Parent squishing rule.** Parent nodes of sub-pages can use terms
   defined by their children (the parent summarizes after children are
   understood). Does NOT apply to same-page siblings.

### Deduction → Verification

10. **Dependencies must be obvious.** Every term in a claim: (a) previously
    defined, (b) being defined now, or (c) common English needing no
    definition.

11. **Vocabulary-building.** Later nodes use ONLY previously defined terms.
    Don't redefine existing terms — reference them.

12. **Name concepts that will be reused.** A reusable concept earns its own
    node.

13. **Final child synonymous with parent.** Reading children in order should
    arrive at the parent's meaning. But don't create redundant echo nodes.

14. **No forced nodes.** Each node = genuine atomic step. Don't create for
    structural completeness — but don't skip steps either.

### Verification by the Reader

15. **Accessibility + precision.** Readable by middle schoolers, precise
    enough for philosophy PhDs.

16. **Steelmanning.** Every objection in its strongest form.

17. **Cost of disagreement.** Every If Rejected shows what specifically
    becomes indistinguishable from what.

18. **Readability over formal minimality.** Technically redundant nodes that
    aid recognition can stay.

## Derivation Principles

### Ordering

- **Break circularity by finding the more primitive concept.** One is always
  more primitive — identifiable from experience without the other. Define it
  first. Example: knowledge (when an answer occurs) before truth (correct
  knowledge).

- **Prefer weaker observational claims over stronger metaphysical ones.**
  "Not all objects are currently observed" rather than "objects exist when
  unobserved."

- **Scope terms before universal claims.** "All" must be defined before "all
  X are Y" claims.

- **Types are children, not siblings.** B is a *type of* A → B is a child
  of A.

- **Group children into sub-pages at ~8+.** Find natural groupings building
  toward a sub-conclusion.

- **Ground rules in observed cases before inducing.** Observe → identify →
  induce. Don't state the rule then justify after.

- **Dependency ordering governs sibling order.**

- **Observe the specific before naming the general.** Observe "necessary"
  and "sufficient" before abstracting "condition."

### Scoping

- **Epistemological scope, not ontological.** These nodes define terms as
  they appear in experience. They don't claim what things are "made of."
  When an objection imports ontological requirements, make the distinction
  explicit.

### Grounding

- **No capacity/possibility language before 1.4.4.1.** "Can," "able,"
  "-able" smuggle in possibility. Use observational language: what *happens*,
  not what *could* happen. Exception: after "possible" is defined, "can"
  is usable. Parent squishing (9b) applies.

- **Ground logical concepts in experiential acts.** Contradiction = trying
  to imagine definitions together and failing. Not an abstract formal rule.

- **Two levels of visualization.** (1) Imagining *definitions together*
  tests compatibility/contradiction. (2) Imagining *the object itself*
  tests comprehensibility. These are independent.

- **Definition is prior to contradiction.** You must know what things *are*
  before discovering their features clash.

- **No causal/agentive language before non-willful causation.** "Make,"
  "determine," "produce," "generate" smuggle in causation beyond willful
  cause (1.2.5.7.8). Use: "correlates with," "independent from," "results
  in," "matches/mismatches."

- **Nest effects under their structural causes.** A phenomenon that exists
  *because of* a structural fact = child of that fact.

- **Observing occurrence ≠ knowing mechanism.** An occurrence earns a node;
  the mechanism is deferred.

### Language

- **Neutral terms when willful connotations are ungrounded.** "Statement"
  (neutral) instead of "claim" (implies asserting).

- **If a definition doesn't match immediate recognition, rework it.** The
  reader should think "yes, that's exactly what I already understand."

- **"Results in" for outcomes.** Maps to "outcome" (1.2.5.1.5) without
  implying causation.

- **"When" is definitional, not temporal.** "Truth is when a description
  matches..." = "the case in which."

- **Never sidestep a definition for convenience.** If a term carries a
  genuine distinction and its prerequisites are met, define it.

- **Term-grounding rules apply to claims, not section content.** Claims
  build the formal vocabulary chain. Section content is explanatory prose
  for a reader who speaks English — it uses whatever words communicate
  clearly.

### Auditing

- **Run dependency audits regularly.** For each term: (a) previously
  defined, (b) being defined, or (c) common English? Flag failures.

- **Parent headers must encompass children with no new information.**

- **Synonym collision check.** One term = one meaning. Rename collisions.

- **Terms must match definitions, not connotations.** Substitute formal
  definition and verify the claim still works.

- **Check if a node says anything new.** If it follows trivially from
  substituting definitions, it doesn't earn a node unless it aids
  recognition AND downstream nodes depend on it.

- **Check where a definition structurally belongs.** Place by dependencies,
  not where first needed.
