# Structural Rules and Derivation Principles

All rules below are specific applications of the writing goal at the top of
`WRITING_GUIDE.md`. They keep the tree's dependency order faithful, each claim
verifiable, and nothing circular.

---

## Formatting conventions

1. **Quotation marks = personal statements only** (Node 1's claim, 1.7). Don't
   quote every claim.

2. **Title prefixes only where they add qualifying context.** *"Phenomenological
   Grounding: ..."* = useful. *"Reasoning verifies..."* = already clear, no prefix
   needed.

3. **Page structure.** 4-space indent = children within the same page. Deeper dot
   notation (*1.2.5.1.x*) = new sub-page.

---

## Structural rules

### Observation → identification → induction

4. **Observation before abstraction.** When a node identifies a general pattern,
   the specific observation grounding it appears first.

5. **States before processes.** When a state and process look interdependent,
   define the state first. The process operates on it.

6. **No circular dependencies.** Every concept in a definition is grounded in a
   prior node or direct observation. If A uses B, B must not use A.

7. **No hidden assumptions.** Every dependency is a prior node or direct
   observation.

8. **Terminal nodes must be self-evident** from direct experience.

9. **Ontological simultaneity, epistemological ordering.** Everything exists
   simultaneously in experience. The tree models the order of *identification*,
   not existence. Each node performs a different epistemic act — noticing something
   new using what was already noticed.

   **9b. Parent squishing rule.** A parent node of a sub-page can use terms
   defined by its children (the parent summarizes after children are understood).
   Does NOT apply to same-page siblings.

### Deduction → verification

10. **Dependencies must be obvious.** Every term in a claim is (a) previously
    defined, (b) being defined now, or (c) common English needing no definition.

11. **Vocabulary-building.** Later nodes use only previously defined terms. Don't
    redefine — reference.

12. **Name concepts that will be reused.** A reusable concept earns its own node.

13. **Final child synonymous with parent.** Reading children in order should arrive
    at the parent's meaning — without creating a redundant echo node.

14. **No forced nodes.** Each node = genuine atomic step. Don't add for structural
    completeness; don't skip steps either.

### Verification by the reader

15. **Accessibility + precision** — the top-level writing goal applied: a smart
    non-expert understands it on first read; a specialist doesn't wince.

16. **Steelmanning.** Every objection in its strongest form.

17. **Cost of disagreement.** Every If Rejected shows what specifically becomes
    indistinguishable from what.

18. **Readability over formal minimality.** Technically redundant nodes that aid
    recognition can stay.

## Derivation principles

### Ordering

- **Break circularity by finding the more primitive concept** — the one
  identifiable from experience without the other. Define it first. *Example:
  knowledge (when an answer occurs) before truth (correct knowledge).*

- **Prefer weaker observational claims over stronger metaphysical ones.** *"Not
  all objects are currently observed"* rather than *"objects exist when
  unobserved."*

- **Scope terms before universal claims.** *All* must be defined before *"all X
  are Y"* claims.

- **Types are children, not siblings.** B is a *type of* A → B is a child of A.

- **Group children into sub-pages at ~8+.** Find natural groupings building toward
  a sub-conclusion.

- **Observe the specific before naming the general.** Observe *necessary* and
  *sufficient* before abstracting *condition*.

- **Dependency ordering governs sibling order.**

### Scoping

- **Epistemological, not ontological.** These nodes define terms as they appear in
  experience. They don't claim what things are *made of*. When an objection imports
  ontological requirements, make the distinction explicit.

### Grounding

- **No capacity/possibility language before 1.4.4.1.** *Can, able, -able* smuggle
  in possibility. Use observational language: what *happens*, not what *could*
  happen. After "possible" is defined, *can* is usable. Parent squishing (9b)
  applies.

- **Ground logical concepts in experiential acts.** *Contradiction* = trying to
  imagine definitions together and failing. Not an abstract formal rule.

- **Two levels of visualization.** (1) Imagining *definitions together* tests
  compatibility/contradiction. (2) Imagining *the object itself* tests
  comprehensibility. These are independent.

- **Definition is prior to contradiction.** You must know what things *are* before
  discovering their features clash.

- **No causal/agentive language before non-willful causation.** *Make, determine,
  produce, generate* smuggle in causation beyond willful cause (1.2.5.7.8). Use
  *correlates with, independent from, results in, matches/mismatches.*

- **Nest effects under their structural causes.** A phenomenon that exists
  *because of* a structural fact = child of that fact.

- **Observing occurrence ≠ knowing mechanism.** An occurrence earns a node; the
  mechanism is deferred.

### Language

- **Neutral terms when willful connotations are ungrounded.** *"Statement"*
  (neutral) over *"claim"* (implies asserting).

- **If a definition doesn't match immediate recognition, rework it.** The reader
  should think *"yes, that's exactly what I already understand."*

- **"Results in" for outcomes.** Maps to *"outcome"* (1.2.5.1.5) without implying
  causation.

- **"When" is definitional, not temporal.** *"Truth is when a description
  matches..."* = *"the case in which."*

- **Never sidestep a definition for convenience.** If a term carries a genuine
  distinction and its prerequisites are met, define it.

- **Term-grounding = claims only.** Claims build the formal vocabulary chain.
  Section content is explanatory prose for a reader who speaks English — it uses
  whatever words communicate clearly.

### Auditing

- **Run dependency audits regularly.** For each term: (a) previously defined, (b)
  being defined, or (c) common English? Flag failures.

- **Parent headers must encompass children with no new information.**

- **Synonym collision check.** One term = one meaning. Rename collisions.

- **Terms must match definitions, not connotations.** Substitute formal definition
  and verify the claim still works.

- **Check if a node says anything new.** If it follows trivially from substituting
  definitions, it doesn't earn a node unless it aids recognition AND downstream
  nodes depend on it.

- **Check where a definition structurally belongs.** Place by dependencies, not
  where first needed.
