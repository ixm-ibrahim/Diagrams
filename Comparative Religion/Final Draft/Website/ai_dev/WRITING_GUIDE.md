# Section Writing Guide

This governs how the *content* of each section is written. Every principle
is an application of the governing goal: readability + precision + atomicity.

---

## The Governing Goal

The content exists to demystify. The reader arrives thinking these concepts
are abstract or academic — and leaves recognizing they already experience
every one. Three requirements, simultaneously:

1. **Incredibly readable.** Lowest possible cognitive load. Every sentence
   does one job. Never re-read to understand.
2. **Logically precise.** Philosophy-PhD rigor. No hand-waving.
3. **Atomic and bite-sized.** One concept per node. The tree decomposes
   complexity so the reader never encounters something that depends on what
   they haven't been shown.

These reinforce each other. Precise definitions are more readable than vague
ones. Atomic chunks force precision. Low cognitive load forces clarity.

**When no rule covers a case, ask:** "What would readability require here?
Precision? Atomicity?" The answer is almost always the right call.

---

## General Principles

**The reader is a conscious person.** You are pointing at what they already
experience, helping them recognize and label it — not writing from some
impossible pre-experiential stance.

**Low cognitive load is the priority.** Natural flowing sentences where each
one does one job. Not choppy fragments, and not dense paragraphs that bury
the point.

**Precision without jargon — but preserve the link.** Plain language, no
loss of rigor. Err conversational over academic. When simplifying a standard
philosophical term, keep the proper term in parentheses: "real, built-in
categories in nature (natural kinds)."

**Grounding over vocabulary.** Foundational nodes establish observations,
not word lists. soWhat, If Rejected, and Conclusion sub-bullets frame the
node as "establishing grounded observations," not "building vocabulary."
Unlocks is the one place vocabulary focus IS appropriate.

**No artificial verbosity.** If it can be said in one sentence, don't use
two. But if it needs two to be clear, use two.

**No formulaic phrasing.** Don't force patterns like "The position that..."
before every Eliminates item, or a fixed number of bullets per section.

**soWhats don't have to be catastrophe-focused.** Definition/grounding nodes
can simply state what the term enables. "Names the phenomenon of connection
between occurrences" is fine.

**Calibrate depth to the node's role.** Definition nodes: lean. Substantive
nodes (non-obvious, serious challenges): deeper. Don't force depth on a
labeling node.

**Reader-facing language only.** No "downstream nodes," "epistemological
branch," "the rest of the tree builds on this." The reader reads a sieve,
not a development log.

### Watch Words

Words that raise cognitive load. Check for simpler alternatives:

- **resolve/resolution** → "ends," "is satisfied," "goes unsatisfied"
- **constitute** → "count as," "amount to"
- **subsume** → "include," "fall under"
- **instantiate** → "is a case of"
- **supervene** → describe the relationship directly
- **entail** → "require," "mean that"
- **posit** → "assume," "claim exists"

Not a ban list — the check is: "Would an average reader understand this on
first pass?"

## Node Function Types

Every node does one of three things. The type determines how sections are
written — especially If Rejected.

**Occurrence nodes** claim a genuinely new phenomenon exists — not
describable using prior vocabulary. If Rejected says "Without X" because
the phenomenon doesn't exist.

**Label/define nodes** name a pattern already describable from prior
vocabulary. Test: can you say what the node says using terms already
established? If Rejected says "Without recognizing X" — the phenomenon
still happens, but can't be referenced compactly.

**Distinction nodes** separate two things that could be conflated. If
Rejected says "Without distinguishing X" — both still exist, but the
difference is invisible.

---

## Observations

Raw material the reader recognizes from their own experience. Things you
point at and the reader goes "yes, I see that."

**What belongs:** Specific, immediate examples. Things verifiable right now.

**What does NOT belong:** The conclusion itself, meta-commentary,
arguments, vocabulary labeling, scoping/framing, explanatory gloss.

### Rules

- **No explanatory gloss.** Each observation is the datum, period. No dash
  followed by clarifying phrase. WRONG: "A sharp pain — vivid, immediate."
  RIGHT: "A sharp pain, right now."

- **Specific examples, not abstract categories.** "Red" — not "a color."

- **Each observation gets its own bullet** when distinct.

- **Cover the range of types at the node's level.** If a node is about
  wanting, show a bodily want, an aversive want, an intellectual want, a
  meta-want. Different KINDS, not variations of one kind.

- **No self-references before 1.3.7.** No "I," "my," "you," "your." Say
  "an arm, felt without looking" — not "your arm's position."

- **Only grounded terms.** Each word must be (a) defined in a prior node,
  (b) the term being defined, or (c) common English with no technical
  weight. Apply the synonym test: if any synonym appears in any node's
  Unlocks, the word is doing philosophical work and needs grounding.

---

## Conclusion

Synthesizes observations into a statement.

- **Conclusion text must be near-verbatim to the node's claim.** Slight
  rewording for readability is fine. No added synthesis, logic, or framing.

- **Supporting points go in nested sub-bullets** (`text`/`items` format):
  vocabulary definitions, why this matters, clarifying scope.

- **Definitions are direct.** Write `A "quality" is a singular distinct
  phenomenon` — not `"Quality" is the label for...`

- **Scoping statements belong in Unknowns or Objections**, not Conclusion.

- **Multiple concluding statements** are fine when a node establishes more
  than one thing.

---

## If Rejected

The specific cost of rejecting the conclusion. Concrete, not vague.

- **Use expandable format** when rejections cascade. Single clear
  consequence = single item without children.

- **Show what becomes indistinguishable from what.** The cost is always a
  loss of distinction.

- **Forward-looking over backward-echoing.** Show what *cannot be built
  later*. An If Rejected that says "this collapses to the previous node"
  is just restating previous work.

- **Apply the "so what?" test.** If the reader can shrug, the consequence
  is too weak. Show something they genuinely care about losing.

- **State the vivid core; don't enumerate.** Make the reader *feel* the
  loss. Do NOT follow with a list of every downstream node that breaks.

- **Match the framing verb to the function type:**
  - Occurrence: "Without X, ..."
  - Label/define: "Without recognizing X, ..."
  - Distinction: "Without distinguishing X, ..."

---

## Unlocks

What accepting this node makes possible. Two categories:

- **Vocabulary** — all common words the node grounds (not just the main
  term). Use nested bullets with main term first, synonyms, then "Also
  grounded" for connector words. Reference the Phenomenology Diagram's
  term sets (PH1–RP5) for guidance.

- **Next steps** — what questions or observations this node enables.

---

## Eliminates

Positions ruled out by accepting this node. Each item: a specific position
someone might hold, stated clearly enough for the reader to evaluate.

---

## Unknowns

What the node does NOT address. Purpose: **scope-guarding against
ontological overreach**. Each Unknown should implicitly address an objection
of "but you're assuming X" by saying "X is not addressed here."

Remove filler items nobody would mistake for overreach. Each item should
name a specific deferred question (cite the node if known).

---

## Objections

Every objection in its strongest form, with four subSections:

- **Objection Basis** — Why someone holds this. The reader who holds this
  view should feel accurately represented. **Address the reader directly**
  — "Maybe wanting is just a label for sensations" rather than
  "Reductionist positions hold that..." The reader should feel like the
  objection is speaking to them, not summarizing a textbook.
- **Objection Commitments** — The **root-cause** assumptions the objection
  requires. Numbered list. Don't list every assumption — isolate the
  specific one(s) that make the objection fail. These are what What's
  Missing will target. If commitment #3 is the load-bearer, commitments
  #1 and #2 should set it up, not be independent claims.
- **What's Missing** — What the objection overlooks. Be specific. Name
  which numbered commitment breaks and why. Target the root-cause
  commitments identified above — not tangential assumptions.
- **Correction** — Shows why the node's claim is validly derived despite
  the objection. Not "the objection is wrong" but what addresses the
  concern while demonstrating the claim still holds. The Correction
  should make clear why the node header follows from the reasoning.

### Rules

- **Weave observations into objections.** The node's observations are not
  arbitrary — they are the experiential data the node is grounded in.
  When someone objects to a node, they implicitly object to the occurrence
  of those observations. Use them as concrete examples in What's Missing
  or Correction where natural: "But consider: hunger is not just stomach
  contractions — it includes a pull toward food."

- **Include real positions people actually hold.** Eliminativism, monism,
  empiricism, etc. But don't fabricate objections nobody holds.

- **If Rejected consequences are objectable.** If someone rejects the claim
  but disputes the consequence, that's a genuine objection to address.

- **Presupposition objections get one core response:** your awareness of X
  is what theories of X are built from. You don't need the theory to have
  the awareness. State the principle, apply it, stop.

- **Force the real commitment.** Don't let the objector off easy. Present
  the genuine dilemma: either [preserves claim] or [specific costly
  commitment the objector must own]. Name the commitment explicitly.

- **No premature commitment in Corrections.** Especially at early levels,
  Corrections must not endorse the node's position as though it were
  already proven. They should be epistemically neutral — showing that the
  objection fails on its own terms. "The question is whether X is part of
  what occurrence IS, or part of how you encounter it" — not "The answer
  is clearly X."

- **Scope-defense must explain, not just assert.** When an objection
  imports vocabulary not yet built (subject, causation, self), don't just
  say "not addressed here." Explain WHY the vocabulary isn't available
  and what the objection would need to show first. When the root issue is
  ungrounded vocabulary, don't agree or disagree with the commitments —
  only address the objection against the node itself.

- **Grounding language in objections too.** The "grounding over vocabulary"
  principle extends to Corrections and What's Missing. Say "this grounds
  the experience of X" — not "this provides vocabulary for X" or "this
  names X for later use."

- **Bullet size discipline.** No single bullet should be a wall of text.
  If a bullet exceeds ~400 characters, split at sentence boundaries or
  restructure with nested `{text, items}` objects. Dense paragraphs in
  single bullets break the demystification goal.

## Parent Synthesis

**Parents encompass their children — they do not come "before" them.**
A parent node is a *summary* read after its children are understood. Parents
can (and should) use terms defined by their children. This is not a
"forward reference" — the parent synthesizes what its children establish.
Act as if all the children are squished into the parent node. (This does
NOT apply to same-page siblings — those follow strict sibling ordering.)

When all children are fleshed out, the parent generalizes:

- **Observations:** Broader phenomenon the children's observations are
  instances of. Don't repeat children.
- **Conclusion:** Near-verbatim to parent's claim. Sub-bullets define terms
  at the parent's level.
- **If Rejected:** Encompasses all children's consequences at parent level.
- **Unlocks / Eliminates:** Union at parent's level of generality.
- **Unknowns:** Generalized unknowns.
- **Objections:** Key synthesis task. Find the higher-level concern that
  encompasses children's objections. Don't list all children's objections
  — generalize.
